# VIAIM Studio — UI Audit & Improvements

> Generated by `improve-ui` skill against the selected surface: the running app shell (App.tsx + 8 component overlays) plus its governing design tokens.

## Design language

- **Audited surface:** The desktop shell of VIAIM Studio (React 18 + Vite + Tailwind + Electron). Specifically the always-on three-pane layout in [`src/App.tsx`](file:///Users/yaban/Desktop/WorkSpace/viaim-notebook-assistant/src/App.tsx), the overlay components in [`src/components/`](file:///Users/yaban/Desktop/WorkSpace/viaim-notebook-assistant/src/components/), and the shared tokens in [`tailwind.config.js`](file:///Users/yaban/Desktop/WorkSpace/viaim-notebook-assistant/tailwind.config.js) + [`src/index.css`](file:///Users/yaban/Desktop/WorkSpace/viaim-notebook-assistant/src/index.css).
- **Design sources:**
  - `tailwind.config.js` — defines the only documented color system (`viaim.bg`, `viaim.card`, `viaim.primary`, etc.), 3 shadows (`glow-primary`, `glow-cyan`, `glow-red`), and 1 keyframe (`wave`).
  - `src/index.css` — defines 1 reusable utility class family (`.glass-panel`, `.glass-floating`) and 1 keyframe (`pulse-ring`).
  - `index.html` — sets `class="dark"` on `<html>` and the body baseline (`bg-viaim-bg`, `text-viaim-textMain`, `select-none`, `overflow-hidden`).
- **Documented decisions:**
  - Dark theme only (`darkMode: 'class'`, `<html class="dark">`).
  - Brand primary = indigo (`#6366F1`); brand accent = cyan (`#00D2BA`); warning = amber; success = emerald; danger = red.
  - Three-tier surface system: `viaim.bg` < `viaim.card` < `viaim.cardHover` with `viaim.border` and `viaim.borderLight` as dividers.
  - Typography hierarchy is implicit: `textMain` for primary copy, `textMuted` for secondary, `textDim` for tertiary. There is no documented size scale beyond Tailwind defaults.
- **Governing owners and consumers:** `viaim.colorTokens` → consumed by Tailwind utility classes (`bg-viaim-bg`, `text-viaim-textMain`, etc.) → composed into components.
- **Explicit exceptions:** None documented. Repository has no `DESIGN.md`.

## Improve first

> **Finding 1** — Replace every `alert()` and the lone `confirm()` with a single toast/confirm subsystem anchored on a documented `Toast` and `Confirm` pattern that lives inside the existing `viaind` token system.
>
> **Why:** The audited surface has a documented and intentional dark/glassmorphism identity (1 utility class family, 1 keyframe, 12 tokens). But 14 OS-native alert calls and 1 native confirm break that identity whenever the product asks the user to confirm anything — which is every cloud-write action, every deletion, and every recoverable error. The product already proves it can build a `viaind`-themed modal primitive (`ConfirmModal.tsx`); the gap is that the rest of the codebase did not adopt it. Fixing this lifts every error message and confirmation into the same visual system the rest of the surface already enforces, with no behavioral change to the actions themselves.
