## 1. 测试范围与策略

被测系统为 Electron 桌面应用 `OpeniFLYTEK`（讯飞 VIAIM 办公本会议助手），核心逻辑在后端 Node 服务（`server/`，24 个模块，约 5.8k 行），前端为 React + Vite。

测试策略按「无副作用、可离线复现」原则设计：

| 层次 | 手段 | 隔离方式 |
| --- | --- | --- |
| 纯函数单元 | 直接 import 纯模块 | 无 I/O |
| 存储层单元 | `MemoryStore` / 临时 SQLite | 显式传入临时目录，不触碰 HOME |
| 服务编排层 | 注入假 `getMeeting` / `read` / `ask`（模拟模型） | 内存替身，无网络 |
| HTTP 契约层 | 真实启动 `server/server.js` 子进程 | 临时 `HOME` + 随机空闲端口 + `VIAIM_MEMORY_SKIP_OFFICIAL=1` |

官方 VIAIM 库（`kitdb.db`）在所有测试中均以只读方式或不接触，`HOME` 全部指向临时目录，不操作用户真实数据。

## 4. 发现的问题

### 4.1 缺陷（建议修复）

**D1｜摘要转写噪音过滤对「无说话人前缀」的行失效（中等）**
`server/summary_service.js:50` 的 `bare.replace(/^[^:：]{1,24}[:：]/, '')` 会把 `📌重点标记点[00:23]` 中的 `[00` 误当作说话人前缀并剥掉匹配段，剩余 `23]` 不再命中噪音正则；纯时间戳行 `00:25` 同样被剥成 `25`。结果：标记点与时间戳行会作为「转写原文」发送给大模型，污染 AI 纪要（用例 15 已固化当前行为）。
建议：把前缀正则收紧为不含 `[`、数字、`:` 的说话人名（如 `/^[^:：\[\]0-9]{1,24}[:：]/`），或在剥离后校验原串是否以已知标记符号开头。

**D2｜官方 VIAIM 库缺失时会议列表整体 500，项目会议不可见（中等）**
`server/server.js:162` 先调 `dbService.getMeetings()`，异常即整体 500，导致项目自有会议（本可正常读取）也不可见；同理 `/api/meetings/:id/generate-ai` 对不存在的会议返回 500 而非 404，`/api/notebook/legacy-imports` 返回 500。在非 macOS/未安装 VIAIM 的环境下影响明显（用例 2、5、7 已按实际行为断言并注释说明）。
建议：官方库不可用时降级为仅返回 `notebookStore.getProjectMeetings()`，并在响应中标注官方数据不可用。

**D3｜后缀 Range 请求 `bytes=-N` 语义错误（低）**
`server/media_stream.js:41` 将 `bytes=-500` 解析为 `start=0,end=500`，返回的是开头 501 字节而非末尾 500 字节。当前前端只发 `bytes=start-`，故未暴露（用例 9 已固化当前行为）。
建议：正则改为区分有/无起始值两组分支。

### 4.2 次要问题 / 观察

1. **`streamLocalMedia` 强依赖 Express 响应对象**（`res.status().json()`），无法在裸 `http` 场景复用；同时是全项目唯一一处非标准 res 用法，建议统一为 `res.statusCode` + `res.json` 或显式注明依赖。
2. **`mergeLeadingPunctuation` 不重排 `ordinal`**（仅 `parseRecordTranscript` 重排），且当上一句已以句末标点收尾时仍会叠加新标点，出现 `结论确定。，下周执行。` 这类瑕疵（用例 6 已记录）。
3. **`normalizeSummary` 丢弃非字符串议题**（数字/对象仅在有 `text`/`title` 时保留），模型若返回数字条目会静默丢失。
4. **无鉴权**：全部 `/api/*` 路由（含 `DELETE /api/notebook/notes/:id` 云端不可逆删除）无任何认证，仅依赖「本机 localhost」假设（`server.js:30` 的 `cors()` 完全放开）。`server.listen(port)` 未显式限定回环地址，不能假定接口仅本机可达；建议单独整改监听策略及本地令牌校验。

## 5. 回归保护的新增不变量

以下断言在本次测试中被固化，后续改动若破坏将立即失败：

- 官方库只读：非项目 id 的待办/删除返回 409，项目音频接口对官方 id 返回 404。
- 存储路径：`..`、绝对路径、`notebook-store-evil` 同前缀兄弟目录、`../../` 文件名一律被拒或剥离。
- Range 流播：200/206/416 语义、`Content-Range` 精确、字节内容一致、`nosniff` 与附件下载头。
- 转写解析：`type=1` 条目计入句子、说话人标记只改说话人不产句、句子 id 为 `{noteId}_{ordinal}`。
- 密钥：`getPublicConfig` 与 `/api/llm/config` 响应中不出现明文密钥，配置文件 0600。
- 文档：内容散列去重、上传名剥离路径成分、目录逃逸 404、原件仅经 `file` 接口下载。

## 7. 缺陷修复复核（2026-10-16）

前述 90 项结果记录的是修复前行为。此次已修改业务代码，D1/D2/D3 的测试改为断言正确行为，而非接受已知缺陷。

- **D1 已修复**：先检查句子原文，再处理嵌入的说话人前缀；标记点、带/不带方括号的纯时间戳均过滤。数字说话人、正文时间、比例和普通冒号内容保留。
- **D2 已修复**：会议列表在官方库缺失或读取失败时保留项目会议，并通过 `sources.viaim` 标记 `available` 与错误码。官方库缺失时，不存在的会议详情/纪要请求返回 404，历史导入候选返回空列表与缺失状态；数据库损坏等真正读取故障不会被吞成 404。`VIAIM_DB_PATH` 可指定只读外部库位置，HTTP 测试固定为临时目录内的缺失路径，避免依赖真实 Mac 数据。
- **D3 已修复**：`bytes=-N` 返回末尾 N 字节，超长后缀夹取整文件；`bytes=-0`、`bytes=-`、空文件范围请求返回 416。大整数范围通过 BigInt 解析，避免精度丢失。
- **次要问题 1 已修复**：媒体流的缺文件响应使用标准 Node HTTP 接口，测试不再需要 Express 响应适配器。
- **其余观察保留**：标点合并与议题类型归一化未改变；全 API 鉴权需独立设计与验收。
- **更正鉴权风险前提**：`server.listen(port)` 没有指定监听地址，日志中的 `localhost` 不能证明仅绑定回环地址，不能以“仅本机可达”降低风险判断。此次未变更网络监听或鉴权协议。
- **验证**：`npm test` 共 93 项通过、0 失败。新增正文冒号/数字说话人保护、空文件范围、官方库损坏与项目会议可用性测试。未调用真实云服务，未重新制作 DMG；此前 DMG 不包含本次修复。
